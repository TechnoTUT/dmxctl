# dmxctl

MIDIパッドやパソコンのキーボードで、DMXの照明機材を操作するコントローラーです(Rust + egui)。
TouchDesignerのような重い映像ソフトと同じPCで動かすことを前提に、常駐中のCPU・メモリを抑えています。

- **操作**: AKAI APC mini mk2(挿せば自動で接続)、または **パソコンのキーボードだけ** でも操作できます。ほかのMIDI機器やOSCも割り当てられます
- **出力**: USB-DMX(FT232系 / Open DMX方式)と Art-Net。複数の出力を同時に使えます
- **内蔵の機材**: MINI SPOT 30(9ch/11ch)、LASER SCAN 300(17ch)、汎用LEDバー(RGBピクセル 1〜32ピクセル)。そのほかの機材も画面で定義を作れます
- **テンポ**: TAP・Ableton Link・MIDIクロック・音声からの自動検出。エフェクトやチェイスは拍に合わせて動きます

## はじめに(最初の準備)

1. **出力** タブで出力先を追加します(USB-DMX か Art-Net)
2. **パッチ** タブで、機材のアドレスを実機の設定(DIPスイッチ・メニュー)と合わせます。手持ちの機材が内蔵に無ければ **機材定義** タブで作ります
3. **MIDI** タブの「配置」メニューから **おすすめ配置** を選ぶと、APC mini mk2 とキーボードの割り当てが、今の機材に合わせてまとめて作られます(今までのAPCの割り当ては置き換わります。元の状態はバックアップに残ります)
4. ムービングがあれば、**キーボード** タブの「向き合わせ」で、真上と正面を1回合わせます([ムービングの動き](#ムービングの動き))
5. レーザーがあれば、**レーザー** タブで「動いてよい範囲」を決めておきます([レーザー](#レーザー))

**タブの使い分け**

| タブ | 使うとき |
|---|---|
| MIDI | 本番のメイン画面。APC mini mk2 と同じ配置の図で、割り当てと今の状態を見る・変える |
| キーボード | MIDIコントローラーが無いとき。キーボードの絵に割り当てが出る。BPMと色のプレビュー、ムービングの向き合わせもここ |
| コントロール | 機材を1台ずつ手で操作する(XYパッド・位置プリセット) |
| エフェクト / シーン / BPM/チェイス / ペア | 演出を作る |
| レーザー | レーザーの位置・大きさ・動いてよい範囲(マウスだけで操作) |
| パッチ / 機材定義 / 出力 / MIDI設定 | 準備・設定 |
| モニター | 実際に送っているDMXの値を見る |

設定は自動で保存されます(Mac: `~/Library/Application Support/dmxctl/`、Windows: `%APPDATA%\dmxctl\`、Linux: `~/.config/dmxctl/`)。

# 本番での操作

## APC mini mk2 で操作する

おすすめ配置にしたときの並びです(MIDIタブの図にも同じものが出ます)。右の列の5番目で 1ページ目(演出)⇄ 2ページ目(設定)を切り替えます。

**1ページ目(演出)**

| 場所 | 中身 |
|---|---|
| パッド 1〜4段 | LEDバーの模様: チル / グルーヴ / ピーク / モノクロ(各8種類) |
| パッド 5段 | ムービングの動きの形: 止める / 円 / 8の字 / 左右 / 前後 / クロス / ランダム / ウェーブ |
| パッド 6段 | ムービングの見た目: 点灯チェイス・ランダム点灯・ブレス・ゴボ切替・ゴボ回転・ゴボシェイク・カラー回転・点灯 |
| パッド 7段 | その他の機材(Twinkle Ball・レーザーの回転/ズーム/描画/7色) |
| パッド 8段 | 押している間だけ: フラッシュ白 / フラッシュ色 / ストロボ / 入れ替え / 消灯 |
| 右の列 | TAP / 頭出し / メイン⇄サブ / 自動入れ替え / ページ切替 / グラデーション / 暗転フェード / BLACKOUT |
| 下の列 | 機種ごとのミュート(LEDバー・ムービング・その他・レーザー) |
| フェーダー | LEDバーの明るさ・速さ・斜め / 機種ごとの明るさ / メイン色・サブ色の色相 / 右端=全体光量 |

**2ページ目(設定)**: 色の系統(メイン/サブ)、1台ずつの系統、**動きの1周の長さ・揃え方**、レーザーのARM、NDI・テンポの元、入れ替えの間隔。フェーダーはムービングの動きの速さと **動きの大きさ**。

## キーボードで操作する(MIDIコントローラーが無いとき)

「キーボード」タブに、実際のキーの並びと同じ絵が出ます。キーの上に割り当てが書いてあり、今効いているものが光ります(絵をクリックしても押せます)。
段ごとに種類をそろえてあるので、絵を見ればすぐ分かります。

| 段 | キー | 操作 |
|---|---|---|
| 数字 | 1〜8 / 9 / 0 | LEDバーの模様(今のセット) / 前のセット / 次のセット(チル→グルーヴ→ピーク→モノクロ) |
| QWERTY | Q〜I / O / P | ムービングの動きの形: 止める・円・8の字・左右・前後・クロス・ランダム・ウェーブ / 動きを小さく / 大きく |
| ASDF | A〜G / H〜K / L / ; | 1周の長さ: 4小節・2小節・1小節・2拍・1拍 / 揃える・ずらす・左右対称 / ゴボ回転 / カラー回転 |
| ZXCV | Z X C / V B N / M , . / | 押している間だけ: フラッシュ白・フラッシュ色・ストロボ / メイン⇄サブ・自動入れ替え・暗転フェード / 向き: 真上・扇形・交差・客席 |

**Shiftを押しながら = 色の段**(Shiftを押している間は、絵も色の段に変わります。「色の段(Shift)」ボタンで出したままにもできます)

| 段 | キー | 操作 |
|---|---|---|
| 数字 | Shift+1〜0 | メイン色: 赤・オレンジ・黄・緑・水色・青・紫・マゼンタ・ピンク・白 |
| QWERTY | Shift+Q〜P | サブ色(同じ並び) |
| ASDF | Shift+A〜K | メイン⇄サブ・自動入れ替え・グラデーション / 入れ替えの間隔 1・2・4・8・16拍 |
| ZXCV | Shift+Z〜C | 色の系統: 全部メイン・全部サブ・LEDバー1本おき |

- 色のキーは、その色で塗ってあります。今のメイン色・サブ色のキーは白い枠で光ります
- キーボードタブの右下に、BPMとメイン色・サブ色のプレビューが出ます

決まったキー:

| キー | 操作 |
|---|---|
| Space | TAP(タップテンポ) |
| Enter | 頭出し |
| ← → | APCのページ(前・次) |
| Esc | ブラックアウト ON/OFF |
| ⌘S / Ctrl+S | 保存 |

- キーボードの割り当ては、マップの「配置」→おすすめ配置で作られます(まだ無いときは、キーボードタブの「キーボードの配置を作る」でも作れます。APCの割り当ては変わりません)
- 割り当ては「MIDI設定」の割り当て一覧で「キー Q」のように表示され、ほかの割り当てと同じように変えられます
- 文字を入力している間(名前の欄など)は、Esc と ⌘S 以外は効きません
- 日本語入力がONのままでも、キーの位置で判定するので効きます
- キーを押したまま別のウィンドウへ移ったときは、押していたキーを全部離したことにします(フラッシュが残りません)

## ムービングの動き

SPOT4と同じく、動きを「形」「1周の長さ」「揃え方」「向き」に分けて、別々のボタンで組み合わせます(例: 円 × 2拍 × 左右対称)。

- **形**: 止める / 円 / 8の字 / 左右 / 前後 / クロス(隣どうしが逆に振れる) / ランダム / ウェーブ(前後の波が左から右へ)。APCの1ページ目5段目、キーボードのQWERTYの段
- **1周の長さ**: 4小節 / 2小節 / 1小節 / 2拍 / 1拍。**揃え方**: 揃える / ずらす(台ごとに少し遅らせる) / 左右対称。APCの2ページ目4段目、キーボードのASDFの段
- **向き**: 真上 / 扇形(外向き) / 交差(内向き) / 客席。もう一度押すと外れて、パン/チルトの今の値(位置プリセットなど)を中心に動きます。キーボードの M , . /
- **大きさ**: APCの2ページ目のフェーダー、キーボードの O / P、キーボードタブのスライダー
- 動かすのは、パン/チルトのある機材(レーザーは除く)。並びはパッチの順(左から)です
- 床置きのムービングを「真上からどちらへ何度傾けるか」で計算するので、真上を通る動きでもパンが急に半回転しません
- 最初に1回、キーボードタブの「向き合わせ」で「真上のTilt」「正面のPan」を合わせてください(SPOT4と同じ手順)
- パン/チルトを動かすエフェクトや位置プリセットを使うと、そちらが優先されます(形は「止める」、向きは外れます)

## レーザー

レーザーは誤操作で客席に向かないよう、ほかの機材と分けて扱います。

- **レーザー** タブで、位置と大きさを **マウスだけ** で合わせます(MIDIのフェーダーやパッドには位置を置きません)。四角いパッドをドラッグすると位置、「範囲を変更」を押してからドラッグすると **動いてよい範囲** を決められます
- 動いてよい範囲は保存され、エフェクト・シーン・MIDIのどれで動かしても、出力の直前に必ずこの中に収めます
- **オートモード・サウンドモードには絶対に入りません**(機材定義の `forbid` で禁止した値は、出力の直前に必ず直します。内蔵の定義を上書きしても引き継ぎます)。パン/チルトの自動の動きの値も禁止しています
- **起動のたびにSAFE**(レーザーOFF)です。ARMしたときだけ出力します(ARMの状態は保存しません)
- BLACKOUT・ミュート・暗転しきったときは、レーザーOFFの値を送ります
- アプリが落ちたとき・終了のシグナル(Ctrl+C など)を受けたとき・**PCのシャットダウンやログオフ**のときは、安全な値(レーザーOFF・明るさ0)を約0.3秒送ってから止まります。強制終了(kill -9)・電源断・USBを抜いたときは送れないので、機材側の「信号が切れたときの動作」に頼ります
- これらは補助です。実機のキースイッチ・インターロックの代わりにはなりません

# 機能の詳しい説明

## MIDIタブ(APC mini mk2 のマップ)

「MIDI」タブは、コントローラーの実機と同じ配置の図です(この説明では「マップ」と呼びます)。

- パッド8×8(Note 0x00〜0x3F、左下が0x00)、シーンボタン(0x70〜0x77、上から)、トラックボタン(0x64〜0x6B)、SHIFT(0x7A)、フェーダー9本(CC 0x30〜0x38、右端がマスター)
- 割り当て済みのコントロールは、動作の種類で色分けして内容を表示(青=チャンネル値 / 緑=シーン / 紫=エフェクト / 赤=ブラックアウト)。空のパッドにはNote番号を表示
- 押している間は明るく光り、フェーダーは現在位置をバーで表示。エフェクトON中・トグルON中も明るくなります
- クリックで右の編集パネルが開き、その場で割り当ての作成・変更・削除・MIDIラーンができます
- 配置と番号は `src/apcmini.rs`(AKAI公式の Communications Protocol v1.0 に基づく)。Session View(初期状態)でのチャンネル1のメッセージが対象です

### 今の色(マップ上部)

マップの上に、各機材が **今実際に出している色** を並べて表示します(DMXの出力値から読み取るので、全体光量・ブラックアウト・エフェクト・チェイス・ピクセルエフェクト・フラッシュがすべて反映されます)。

- 1色の機材は色見本。暗いほど明るさ(ディマー・全体光量)が低く、消えているときは斜線。カラーホイールの色は、機材定義の範囲の色(名前か、指定した色)で表示します(分からない色は「?」)
- LEDバーは、ピクセルごとの色の帯
- ARMしていないレーザーは「SAFE」、ブラックアウト中は「BLACKOUT」
- 右側に、今のメイン色/サブ色(入れ替え中はその表示)
- マウスを乗せると、色の名前と明るさ(%)
- エフェクトなどで色がひとりでに変わっている間は、マップを1秒に4回更新します(ウィンドウが前面のときだけ)

### フェーダーの連動

- 実機のフェーダーを動かすと、図のフェーダー(バー+白いつまみ)がリアルタイムに追従します
- 接続した瞬間に、APC mini mk2 へ Introduction Message(SysEx)を送って9本の現在位置を読み取るため、動かす前から正しい位置が表示されます。「フェーダー位置を読み取る」ボタンで読み直せます
- 読み取った位置は**表示だけ**で、割り当ての動作(機材の出力)には反映しません。接続した瞬間に機材が動いたり、レーザーが出たりしないようにするためです。動かしたときから値が効き始めます

## パッドのLED(APC mini mk2)

割り当てのあるパッド/ボタンが光ります。APC mini mk2 に接続している間だけ動き、切断・終了時には全部消灯します。MIDIタブの「パッドのLEDを点灯」でON/OFF、「待機中の明るさ」(10% / 25% / 50%)を変えられます。

**色**(動作の種類)

| 動作 | 色 |
|---|---|
| シーン呼出 | 緑 |
| エフェクト | 紫 |
| チェイス | 黄 |
| ペア | ピンク |
| ブラックアウト | 赤 |
| テンポ(TAP等) | 水色 |
| 位置プリセット | 水色(最後に呼んだ位置が明るく光る) |
| ページ切替 | 白(今のページが明るく光る。右の列のボタンなら点滅) |
| チャンネル値 | 青。ただしカラーなどを選ぶパッドは、選ぶ色(赤/緑/青/黄/オレンジ/白…)そのもの |

**明るさ**

- 待機中(割り当てはあるが、効いていない): 暗め
- 効いている間: 最大。エフェクトON・チェイス動作中・ペアON・ブラックアウト中、トグルON、いま選ばれている色/値、最後に呼んだシーン(ラジオボタンのように1つだけ)
- 押している間: 白
- **TAPのパッド**: 拍に合わせて点滅します(小節の頭=1拍目だけオレンジ)
- 割り当てのないパッド: 消灯

**実際の色で光らせる(フルカラー)**: 次のパッドは、128色のパレットから近い色を選ぶ代わりに、APC mini mk2 のフルカラー指定(SysEx「RGB LED Color Lighting」)で **実際の色(RGB)** に光ります。待機中は暗め、選ばれている色は最大の明るさです。画面のマップのパッドも同じ色で表示します。

- 色(全体制御)のパッド、メイン色/サブ色のパッド: その色(カラーピッカーで作った色や、パレットに無い色もそのまま)
- 「チャンネル値」でカラーホイールなどの色を選ぶパッド: その範囲の色(機材定義で指定した色)
- 機材選択のパッド: **その機材が今出している色**(LEDバーは1番目のピクセル)
- メイン⇄サブ入れ替えのパッド: 今メインの機材に出ている色
- 「MIDI/OSC」タブの「色のパッドは実際の色で」をOFFにすると、従来どおりパレットの近い色で光ります(実機で色がおかしいときはOFFに)

**右の8ボタン(シーン)と下のボタン(トラック)** は単色LEDのため、割り当てあり=点灯、効いている間=点滅です。SHIFTとフェーダーにはLEDがありません。

仕組み: 通信仕様書どおり、パッドは Note On のベロシティ=色、MIDIチャンネル=明るさで送ります。変化があったところだけ送り、3秒ごとに全部を送り直します(実機側の状態が変わっても戻るように)。

## パッドのページ

APC mini mk2 の64パッドを、**8ページ**に分けて使えます(例: ページ1=色、ページ2=位置、ページ3=エフェクト)。

- 割り当てごとに「全ページ共通」か「ページNだけ」を選びます。今のページの割り当てと、共通の割り当てだけが反応・点灯します
- ページの切り替え: 動作「ページ切替」(ページNへ / 次へ / 前へ)。マップの「**ページ切替を配置**」で、右の列のシーンボタン1〜8を「ページ1〜8へ」にします(使用中のボタンは飛ばします)。マップ上部のページ番号をクリックしても切り替わります(実機も同じページになります)
- マップは今のページを表示します。ページを使っているとき、マップで新しく作るパッドの割り当ては、表示中のページ専用になります(ボタン・フェーダーは共通)
- 既存のプロジェクトは全部「全ページ共通」のままです。「共通のパッド N件をページN専用にする」ボタンで、パッドの割り当てをまとめて今のページへ移せます
- パッドを押したままページを切り替えても、離したときは元の割り当てに届きます(押している間の動作が戻らなくなることはありません)。フェーダーは今のページの割り当てにだけ効きます

## 機材定義とカテゴリ

**機材定義** タブで、機材・モード・チャンネルを画面上で作れます。保存すると、その場で配置済みの機材にも反映されます(値は機能名 `attr` で引き継がれ、増えたチャンネルは初期値になります)。

- チャンネルごとに 名前 / 機能名(`attr`) / **カテゴリ** / 初期値 / 安全値 / 16bit(下位バイト) / 値の範囲(選択肢)を設定
- 値の範囲に名前を付けると、コントロール画面では選択式になります(色・ゴボなど)。「連続」は範囲内の値が速度などの意味を持つ場合、「注意」はリセットなど誤操作したくない項目に使います。「N個に均等分割」で一括作成も可能
- 「Pan/Tilt (16bit)」「RGB」「ディマー」はワンクリックで追加。チャンネルの並べ替え・削除をしても、16bitの紐付けは自動で追従します
- 保存前に、機能名の重複・16bit指定の誤り・レンジの抜け/重複を検出して知らせます
- 内蔵の機材を編集すると、元の定義とは別のファイルとして保存されます。「初期状態に戻す」で削除して元に戻せます

**カテゴリ**(標準: 動き / 色 / 光量 / 形 / 制御 / その他。自由に追加可)

- コントロール画面が、機材ごとにカテゴリ別にまとまり、上のボタンで表示するカテゴリを絞り込めます(「動きだけ見たい」など)
- シーンを「保存する項目」で絞って保存できます。「動きだけ」のシーンと「色だけ」のシーンを別々に作って、パッドで組み合わせて呼び出せます。「現在値で上書き」は、その部分シーンのまま更新します

## 全体光量(マスター)

すべての機材のディマーにかかる、全体の明るさのつまみです。

- **初期割り当て: 右端のフェーダー**(APC mini mk2 のマスターフェーダー、CC 0x38)。画面上部の「全体光量」スライダーでも操作できます
- 割り当ては、マップ/MIDIタブの動作「全体光量」として他のフェーダーやノブ、パッドにも変更できます(パッドなら「押している間」「トグル」などで ON時/OFF時の%を指定)
- 掛かる先: 各機材の `dimmer` チャンネル。ディマーが無い機材(RGBだけの灯具など)は、`red / green / blue / white / amber / uv` に掛けます。Pan/Tiltやストロボ、レーザー(ディマーなし)には影響しません。元の値(ベース値)は変わらないので、全開に戻せばそのまま戻ります
- APC mini mk2 と接続した瞬間に、実機のマスターフェーダーの位置を読み取って出力も合わせます(下まで下げてあれば、暗い状態から始まります)。他の割り当ては接続時には動かしません
- 起動時の既定は全開(100%)です。値は保存しません。既存のプロジェクトにも、一度だけ右端のフェーダーへ自動で割り当てます(消したものは復活せず、右端のフェーダーが別の用途なら上書きしません)

## BPM・チェイス

**テンポ(BPM)** は全体で共通の1つです。画面上部(2段目)と「BPM/チェイス」タブで操作できます。

- BPMの直接入力(20〜300)、**TAP**(叩いた間隔の平均からBPMを決め、拍の位置も叩いたタイミングに合わせます。2秒以上空くと数え直し)、**頭出し**(拍の位置を小節の頭へ)、÷2 / ×2
- 拍の表示: 上部のドットが1小節(4拍)を表します(1拍目はオレンジ)。テンポを変えても、拍の位置は飛ばずに連続します
- **MIDI割り当て**(動作「テンポ」): TAP / 頭出し / BPM調整(フェーダーで最小〜最大BPMを指定) / BPM ±(ボタン1回で増減)

**エフェクトのBPM同期**: エフェクトの「速さ」を「BPM同期: N拍で1周期」にすると、拍に合わせて動きます(16/8/4/2/1/0.5/0.25拍、または任意の拍数)。テンポを変えても位相はずれません。「自由(Hz)」に戻せば従来どおりです。

**チェイス**: シーンをBPMに合わせて順番に呼び出します。

- 1ステップの長さ(拍)、フェード(拍。0=カット)、順序(順番 / 往復 / ランダム)を指定。フェードの秒数はBPMから計算されるので、テンポを変えても拍に対する長さは変わりません
- ランダムは、1周ごとに全ステップを一度ずつ、順番をシャッフルして出します(同じステップが続きません)
- 「色だけ」「動きだけ」など部分シーンを使えば、複数のチェイスを同時に動かして、色と動きを別々のテンポで回せます
- チェイスのON/OFFは動作「チェイス」でパッドに割り当てられます(トグル / 押している間 / ワンショット)。動作中のステップは一覧に▶で表示されます
- チェイスによる値の変化は一時的なものとして扱い、自動保存の対象にしません

## ペア(連動・左右反転)

**ペア** タブで、2台の機材を組にします。「元」の機材の動きに「ペア相手」が連動し、指定した機能は反転できます(例: 左右対称に動かす)。

- ペア相手は、元の機材の**最終的な値**に追従します。手動操作・エフェクト・シーン・チェイス・全体光量のどれも、元の機材に対して行えば、ペア相手にも(反転して)反映されます
- **左右反転**: 反転する機能を選びます(既定は `pan`)。値は 0↔255(16bitの Pan は 16bit精度で反転)。レンジ付きの機能(レーザーのパン位置など)は、連続レンジの中でだけ反転し、マクロなど選択式の値は変えません
- **連動しない項目**: カテゴリ単位で外せます(既定は「制御」。リセットなどのマクロまで連動させないため)
- **連動と反転は別のスイッチ**: 連動ON + 反転OFFなら「同じ動き」、連動OFFなら独立に戻ります。どちらも MIDI の動作「ペア」でパッドに割り当てられます(トグル / 押している間)
- 同じ機種どうしなら、カラーやゴボのような選択式も連動します。機種が違う場合は、選択式チャンネルは値の意味が違うため連動せず、スライダー式のチャンネルだけが同じ機能名(`attr`)で対応します
- ペア相手のチャンネルは、連動している間、コントロール画面で操作できません(連動後の値を灰色で表示し、「ペア: ○○ に連動中」と出ます)。ペア相手自身の値は書き換えないので、連動をOFFにすればすぐ元に戻ります
- ペア相手に直接かけたエフェクトは、連動しているチャンネルについては元の機材の値が優先されます

## フラッシュ

動作「**フラッシュ(全開)**」をパッドに割り当てると、押している間だけ全機材を全開にします(「トグル」も可)。

- **元の値は変えません**(離すと、フラッシュ前の明るさ・色にそのまま戻ります)。「チャンネル値」の「押している間」は離すとOFF値になるので、明るさを戻したいときはフラッシュを使います
- 「白で全開」: 色も白にする / OFF: 今の色のまま全開(LEDバーはピクセルごとの色のまま、いちばん明るく)
- 全体光量より優先します。ブラックアウト中は光りません。**レーザー(ARMが必要な機材)には掛かりません**
- OSC: `/dmx/flash 1/0`(白)、`/dmx/flash/color 1/0`(今の色のまま)

## 暗転フェード

上部の「**暗転**」(キーボードでは N)で、全体の明るさを右の秒数(既定3秒)をかけて0にします。もう一度押すと同じ秒数で戻ります。

- 全体光量と同じところにかかります(元の値は変えません)。途中の明るさはボタンに%で出ます
- 暗転しきると、ブラックアウトと同じ扱いになります(レーザーなど明るさのチャンネルが無い機材も止まり、フラッシュも効きません)
- パッドに割り当て: 動作「**暗転フェード**」(秒数を指定。トグル=押すたびに暗転⇄復帰 / 押している間=離すと戻る)。暗転中はパッドが光ります
- OSC: `/dmx/fade 1`(暗くする)/ `/dmx/fade 0`(戻す)。2つ目の数値で秒数(例: `/dmx/fade 1 8`)。`/dmx/fade/time 5` で標準の秒数

## 色の全体制御・全体/個別スイッチ

「赤」「青」といった**色そのもの**を指定すると、機材ごとの仕組みに合わせて設定されます。機種が違っても、1つのパッドで全体の色を揃えられます。

| 機材の種類 | 設定のしかた |
|---|---|
| RGB(`red / green / blue`)の灯具 | その色のRGB値。`white` があるRGBWは、共通成分を白チャンネルに回す |
| カラーホイール・色レンジの機材(MINI SPOT、LASERなど) | 「color」チャンネルの色レンジ(名前が赤/青/ライトブルー…の単色のもの)のうち、一番近い色 |
| 上記どちらも無い機材 | 変わらない |

- 明るさ(ディマー)には触れません。全体光量とは独立です
- 色はシーンにも保存されます(シーンの「保存する項目」を「色」だけにすれば、色だけのシーンになります)

**全体/個別スイッチ**

- **全体**: 全機材に色がかかる / **個別**: 選択中の機材だけにかかる(起動時は全体、個別の初期選択は先頭の機材)
- 切り替え: 画面上部の「色: 全体/個別」ボタン、または MIDI の動作「色:全体/個別 スイッチ」(押すたびに切替 / 押している間だけ個別 / 全体にする / 個別にする)
- 個別モードで色をかける機材は、上部に出る機材名のボタンで選択/解除(複数可)、または MIDI の動作「機材選択」(この機材だけを選ぶ / 選択に追加・解除)
- コントロールタブの上部に、色パレット(10色)と色相スライダーがあります。操作先は上のスイッチに従います

**MIDI割り当て**(動作「色(全体制御)」)

- 色を選ぶと、そのパッドで押した瞬間にその色になります。「色相(フェーダー)」を選ぶと、フェーダー/ノブで **HSVの色相H** を連続で動かせます(下記)
- 操作先は「全体/個別スイッチに従う」(既定) / 「常に全機材」 / 「常に選択中の機材」から選べます
- マップの「**色の操作を配置**」ボタンで、空いているところにまとめて割り当てます: 下段のパッド8個=色(赤・オレンジ・黄・緑・水色・青・紫・白)、右下のシーンボタン=全体⇄個別、トラックボタン1〜8=機材の選択(機材の順)、**フェーダー8=色相(H)**。使用中のボタンは飛ばします
- APC mini mk2 のLED: 色のパッドはその色で光り、最後に選んだ色が明るくなります。個別モード中と、選択中の機材のボタンは点滅します

### メイン色 / サブ色(色の2系統)

機材を **メイン** と **サブ** に分けて、2つの色を出し分けます。**入れ替え**で一瞬で色を交換できます。

- **割り当て**: コントロールタブの「出す色:」で、機材ごとに メイン / サブ / 対象外 を選びます(既定はすべてメイン)。同じ機種が複数あるときは「機種ごと」でまとめて選べます。例: スポット=メイン、レーザー=サブ にすると、機種ごとに別々の色になります
- **色の決め方**:
  - 「メイン/サブ:」の色見本をクリックすると、カラーピッカーで自由に選べます
  - 色の行の操作先を「→メイン」「→サブ」にすると、色ボタン(10色)とHスライダーで、その系統の色を決められます(「全体」に戻すと従来どおり機材に直接かけます)
- **入れ替え**: 「⇄ 入れ替え」で、メインの機材にサブ色、サブの機材にメイン色が出ます(もう一度で戻る)。全部メインにしておけば、「全体がメイン色 ⇄ 全体がサブ色」の切り替えになります
- **拍で自動入れ替え**: チェックを入れると、指定した拍数ごとにメインとサブが自動で入れ替わります(BPM・Link・MIDIクロックに同期)。自動入れ替えによる色の変化は、自動保存のきっかけにしません
- 対象外の機材は、メイン/サブの操作では色が変わりません
- **MIDI割り当て**: 動作「色(全体制御)」の操作先に「メイン色にする」「サブ色にする」(色パッド・色相フェーダーどちらも可)。動作「メイン/サブ色 入れ替え」(押すたびに入れ替え / 押している間だけ入れ替え / 拍で自動入れ替え ON/OFF)
- マップの「**メイン/サブ色を配置**」: 下から2段目のパッド8個=メイン色、3段目=サブ色、シーンボタン7=入れ替え、6=自動入れ替え(使用中ならトラックボタン8・7)、フェーダー6・7=メイン・サブの色相。使用中のところは飛ばします
- LED: 今のメイン色/サブ色のパッドが明るく光り、入れ替え中・自動入れ替え中のボタンは点滅します
- OSC: `/dmx/main 赤`、`/dmx/sub blue`、`/dmx/main/hue 0.5`、`/dmx/swap`、`/dmx/swap/auto 1`
- メイン/サブの色は、使ったとき(色を決めた・入れ替えた・割り当てを変えた)にだけ機材へ出ます。他の色の操作(直接の色パッド、シーン、チェイス)で上書きした色は、次にメイン/サブを操作するまでそのままです

### 色相H(HSV)のフェーダー

- フェーダーの全行程で、色相環を**0〜360°**一周します(下端=0°=赤 → 60°=黄 → 120°=緑 → 180°=水色 → 240°=青 → 300°=マゼンタ → 上端=360°=赤に戻る)。彩度・明度は最大で、明るさは全体光量/ディマーで別に決めます
- 割り当て: マップ/MIDIタブの動作「色(全体制御)」→「色相(フェーダー)」。マップの「色の操作を配置」で、フェーダー8(右から2番目)に自動で入ります
- 操作先は「全体/個別スイッチに従う」(既定)/「常に全機材」/「常に選択中の機材」から選べます
- RGBの灯具は、その色相そのままの色になります。カラーホイール・色レンジの機材(スポット、レーザー)は、その色相に一番近い色のレンジに切り替わるため、フェーダーを動かすと色が段階的に切り替わります
- 表示: マップのフェーダーは、値の代わりに**度数**を出し、バーもその位置の色で塗ります。コントロールタブの「H」スライダー(度数と色見本つき)は、実機のフェーダーを動かすと一緒に動きます。スライダーを直接動かしても同じ操作になります
- APC mini mk2 の接続時に読み取るフェーダーの初期位置は、色相には反映しません(接続した瞬間に色が変わらないよう、動かしたところから効きます)

### 範囲ごとの色(カラーピッカー)

機材定義エディタの「値の範囲・選択肢」で、各範囲に**その範囲が出す色**を指定できます(「色」にチェック → カラーピッカーで選ぶ)。レーザーやカラーホイールの「DMXのこの値はこの色」を、名前に関係なくソフト内で決められます。

- 色を指定した範囲は、**表示名に関係なく**その色として扱います(「ネオンピンク」でも、「赤/緑」のような複数色の名前でも使えます。名前が「赤」でも、指定した色が優先されます)
- 「色」にチェックがない範囲は、従来どおり表示名の色の名前(赤・緑・青・黄・白・紫・オレンジ・ピンク・マゼンタ・シアン・ライトブルー)から判定します。判定できた色は見本として表示され、判定できない範囲は「色なし」と出ます(色の全体制御・色相フェーダーの対象外)
- 使われる場所: 色の全体制御(赤・青などのパッド)、色相フェーダー、パッドのLEDの色(パレットの一番近い色)、コントロールタブのドロップダウンの色見本
- 「色」にチェックを入れた直後は、名前から判定した色(判定できなければ白)が初期値になります
- 保存される定義ファイルには、色を指定した範囲だけ `"color": [R, G, B]` が入ります(古い定義もそのまま読めます)

## LEDバー(RGBピクセル)

DMXで **RGBRGBRGB…** とピクセルが並んでいるLEDバーを扱えます。

**機材の追加**: 「パッチ」タブで **LEDバー (RGBピクセル)**(内蔵・汎用)を追加し、モードを実機のチャンネル数に合わせます(3ch=全体で1色 / 12ch=4ピクセル / 18ch=6 / 24ch=8 / 30ch=10 / 36ch=12 / 48ch=16 / 72ch=24 / 96ch=32)。実機のDMXアドレスも合わせてください。

- 上記に無いピクセル数や、色の並びが **GRB / BGR / RGBW** などの機種、先頭にディマーやストロボのチャンネルがある機種は、「機材定義」タブの「まとめて追加 → **RGBピクセル (LEDバー)…**」で作れます(ピクセル数と色の並びを指定。既にピクセルがあれば続きの番号から追加)
- ピクセルのチャンネルの機能名は `red.1` `green.1` `blue.1` `red.2` … です。番号なしの `red` を指定すると全ピクセルの赤になります(MIDI割り当て・エフェクト・OSC `/dmx/fixture/<ID>/red`)。1ピクセルだけなら `red.3` のように指定します

**これまでの機能はそのまま効きます**

- 色の全体制御(色ボタン・色相フェーダー)、**メイン/サブ色**(LEDバーをメインかサブに割り当て)、シーン(ピクセルごとの値を保存)、全体光量(ディマーの無いバーはRGBにかかる)、ブラックアウト(ピクセルは消灯)

**コントロールタブ**: LEDバーは、ピクセル数ぶんのスライダーの代わりに、**今の出力を色の帯で表示**(エフェクト・全体光量込み。画面の更新は操作時と拍ごと)し、「全体」の色見本で全ピクセルの色、「ピクセルごとの色」で1つずつの色を選べます。

**ピクセルエフェクト**(「エフェクト」タブの下): バーに沿って動く色の模様です。速さはBPMに同期(1周の拍数)。

| 種類 | 動き | 「幅」の意味 |
|---|---|---|
| レインボー | 色相がバーに沿って流れる | 繰り返し回数 |
| 流れる点 | 色Aの点が色Bの上を1ピクセルずつ進む | 点の幅 |
| ワイプ | 色Aで端から埋め、次に色Bで埋め戻す | - |
| 交互 | 色Aと色Bを交互に並べ、1周ごとに入れ替え | 1色の幅 |
| きらめき | 色Bの上に色Aがランダムに光る(1周に8回選び直す) | 光る数 |
| グラデーション | 色A→色Bのグラデーションが流れる | 繰り返し回数 |
| 流れる縞 | 色Aと色Bの縞が1ピクセルずつ流れる(1周で縞2本分) | 縞の幅 |
| ウェーブ | 色Aと色Bがなめらかな波になって流れる | 繰り返し回数 |
| 交互ウェーブ | 隣り合う組が、色A⇄色Bを逆向きにふわっと行き来する | 1色の幅 |

**メイン/サブの模様プリセット**: 「＋ メイン/サブの模様プリセット」から、メイン色とサブ色を混ぜる模様を追加できます(OFFの状態で追加。「全部まとめて追加」もあり)。

| プリセット | 中身 |
|---|---|
| 縞々 | 2ピクセルずつの縞(止まったまま) |
| 縞々スクロール / 太縞スクロール | 縞(幅2 / 幅4)が流れる(4拍 / 8拍で1周) |
| 交互チェンジ | 1ピクセルおきの縞が、拍ごとに入れ替わる |
| ウェーブ / 細かいウェーブ | メインとサブの波が流れる |
| 交互ウェーブ | 隣どうしが逆向きにメイン⇄サブを行き来する |
| センターウェーブ / センター縞 | 中央から左右対称に広がる |
| グラデーション / メイン点が走る | メイン→サブのグラデーション / サブの上をメインの点が走る |

- メインとサブの色を変えたり、入れ替え・拍で自動入れ替えをすると、模様の色もそのまま変わります
- マップの「**LEDバーの模様を配置**」: 先頭の8種類を、パッドの最上段に「トグル」で並べます(使用中のパッドは飛ばして次の空き、2段目まで。置いてある模様は二重に置きません。ページを使っているときは表示中のページに置きます)
- **1本のバーに出る模様は1つずつ**: 模様をONにすると、同じバーに掛かっている他のピクセルエフェクトは自動でOFFになります(パッドで次々に切り替えられます)。別々のバーに掛けた模様は同時に動きます
- 「中央から左右対称」: どの模様も、中央から外へ広がる形にできます

- 色A/色Bは **メイン色 / サブ色**(入れ替え・拍での自動入れ替えにも追従)、消灯、白、指定の色から選べます
- 「複数台を1本につなげる」: 複数のバーを、パッチの順に1本の長いバーとして流します(OFFなら各台で同じ動き)。「逆向き」で流れる向きを反対に
- ON/OFFは、通常のエフェクトと同じく動作「エフェクト」でパッドに割り当てます(同じ名前ならまとめてON/OFF)。OSCは `/dmx/effect 名前 1/0`
- ピクセルエフェクトは出力だけを変えます(ベース値は変わらないので、OFFにすれば元の色に戻ります)

## 位置プリセットとXYパッド

- **XYパッド**: パン/チルトのある機材には、コントロールタブの「動き」の先頭に四角いパッドが出ます。ドラッグで 横=パン / 縦=チルト を同時に動かせます。**Shift+ドラッグ**で細かく動きます(16bitの機材は下位バイトまで)。ペアで連動中の機材は、連動後の位置を表示するだけで動かせません
- **位置プリセット**: コントロールタブ上部の「位置:」で、今のパン/チルトを名前付きで保存し(「客席」「天井」「ミラーボール」など)、ボタンで呼び出します。フェード時間(秒)を付けられます。右クリックで フェードの変更・今の位置で上書き・削除
- 記録するのは、パン/チルトを持つ全機材の `pan` と `tilt` だけです(光量や色は変えません)
- パッドへの割り当て: 動作「位置プリセット」。OSCからは `/dmx/position 名前`

## 映像ソフトとの連携(Ableton Link / MIDIクロック / OSC)

### テンポの同期

「BPM/チェイス」タブの **同期 → テンポの元** で選びます。上部のBPMの横に状態が出ます(`Link 2` = つながっているアプリ数 / `CLK` = MIDIクロック受信中)。

| テンポの元 | 動き |
|---|---|
| 内部(既定) | このアプリのBPM(TAP・手入力) |
| **Ableton Link** | 同じPC・同じネットワークのLink対応アプリ(TouchDesignerの **Ableton Link CHOP**、Resolume、Ableton Live、DJソフトなど)と、**テンポと拍の位置(小節の頭)**が揃います。相手のテンポ変更に追従し、ここでのTAP・BPM変更・頭出しも相手に伝わります |
| MIDIクロック | 外部から来るMIDIクロック(1拍24回)でテンポと拍を決めます。Start(0xFA)で小節の頭に揃います。クロックが途切れたら、最後のテンポのまま内部で走り続けます(照明は止まりません)。入力はメインのMIDI入力か、別のポート(loopMIDIなどの仮想ポート)を選べます。クロック中はBPMの手入力とTAPは効きません |

- Linkは公式のC++実装(Ableton Link 4)をそのまま組み込んでいます。初めてLink/OSCを有効にしたとき(exeの場所ごとに1回)、Windowsのファイアウォールの確認が出ます(Linuxでファイアウォールを有効にしている場合は [Linux で使う](#linux-で使う) を参照)。別のPC(映像用PCなど)とつなぐ場合は「許可」が必要です
- TouchDesignerでは、Ableton Link CHOP の `Enable` をONにするだけで、このアプリとテンポ・拍が揃います。Beat CHOPなどの映像の動きと、照明のBPM同期エフェクト・チェイスが同じ拍で動きます

### OSC受信

「MIDI/OSC」タブの **OSCを受信** をONにします(UDP、既定のポート9000)。TouchDesignerなら OSC Out CHOP / OSC Out DAT から送ります。

- **割り当てにOSCアドレスを付ける**: 割り当て(マップ/MIDI/OSCタブ)の「OSC」欄にアドレスを書くか、「OSCラーン」を押してから送ると登録されます。MIDIと同じ動作を、OSCでも実行できます(MIDIとOSCの両方を付けてもよい)。値は0〜1(フェーダー系はそのまま、ボタン系は0.5以上で押した扱い、値なしは1回押した扱い)。OSCの割り当てはページに関係なく反応します
- **決まったアドレス**(割り当てなしで使える。一覧は画面の「OSCで使えるアドレス」)

| アドレス | 内容 |
|---|---|
| `/dmx/master f` | 全体光量(0〜1) |
| `/dmx/blackout f` | 1=ON / 0=OFF |
| `/dmx/bpm f` / `/dmx/tap` / `/dmx/resync` | BPM(数値)/ タップ / 頭出し |
| `/dmx/scene s` / `/dmx/position s` | シーン / 位置プリセットを名前で呼び出す |
| `/dmx/color s` / `/dmx/hue f` | 色(`赤` / `red` など)/ 色相(0〜1で一周)。全体/個別スイッチに従う |
| `/dmx/main s` / `/dmx/sub s` | メイン色 / サブ色(`/dmx/main/hue f`・`/dmx/sub/hue f` で色相) |
| `/dmx/swap` / `/dmx/swap/auto f` | メイン⇄サブ入れ替え / 拍で自動入れ替え(1/0) |
| `/dmx/main/rgb f f f [秒]` / `/dmx/sub/rgb f f f [秒]` | メイン色 / サブ色をRGBで(0〜1。0〜255でもよい)。受けた色へ**なめらかに**近づく。4つ目の数値で近づく速さ(秒) |
| `/dmx/main/rgb/at f f f 秒` / `/dmx/sub/rgb/at …` | 先読みした色: その秒数後に**ちょうどその色**になるよう、まっすぐ近づく(遅れを打ち消す用。Beat Link Trigger の例を参照) |
| `/dmx/rgb/smooth f` / `/dmx/rgb/off` | RGBで受けた色へ近づく標準の速さ(秒。0ですぐ。画面でも変えられる)/ RGBの色をやめてパレットの色に戻す |
| `/dmx/level f [秒]` / `/dmx/level/at f 秒` | 明るさ(0〜1。波形の大きさなど)。全体光量に掛ける。色と同じく、なめらかに / 先読みで近づく |
| `/dmx/level/depth f` / `/dmx/level/off` | 明るさの効き具合(0=効かない〜1=0のとき真っ暗。標準 0.7。画面でも変えられる)/ やめる |
| `/dmx/phrase s` | 曲のフレーズ(`intro` / `verse` / `chorus` / `bridge` / `up` / `down` / `outro`)。下の [Beat Link Trigger との連携](#beat-link-trigger-との連携) を参照 |
| `/dmx/effect s f` / `/dmx/chase s f` | エフェクト / チェイスのON/OFF(名前, 1/0) |
| `/dmx/page i` | パッドのページ(1〜8) |
| `/dmx/fixture/<ID>/<機能> f` | 機材1台のチャンネル(0〜1)。例 `/dmx/fixture/1/dimmer` |
| `/dmx/all/<機能> f` | 全機材のチャンネル(0〜1)。例 `/dmx/all/pan` |

- バンドル(`#bundle`)にも対応。OSCを連続で受けていても、画面の更新は0.25秒に1回までに抑えています
- RGBで受けた色は保存しません。パッドや画面で手で色を選ぶと、そちらが効きます(RGBの受信はやめた扱い)。NDIの色を使っている系統では、NDIの色が優先です

### Beat Link Trigger との連携

[Beat Link Trigger](https://github.com/Deep-Symmetry/beat-link-trigger)(BLT)を使うと、CDJ / XDJ などのDJ機器から、テンポ・波形の色・曲の構成(フレーズ)を受け取って照明に使えます。

- **テンポ**: BLT の Ableton Link の機能でマスタープレイヤーのテンポと拍を Link に流し、このアプリのテンポの元を「Ableton Link」にします([テンポの同期](#テンポの同期))
- **波形の色 → メイン色**: BLT から、**少し先の位置**の波形の色を `/dmx/main/rgb/at r g b 秒` で送ります。このアプリは「その秒数後にちょうどその色」になるよう、まっすぐ色を変えていきます。BLT が状態を受ける間隔(約0.2秒)・ネットワーク・照明の反応の遅れを先読みで打ち消すので、曲と色がずれません。次の色が届くと、そこからまたつながるので、途切れずになめらかに変わります
  - 先読みしない `/dmx/main/rgb` でも使えます(受けた色へなめらかに近づく。そのぶん少し遅れます)
- **波形の大きさ → 明るさ**: 同じように `/dmx/level/at 大きさ 秒` で送ると、曲の大きい所で明るく、静かな所で暗くなります(全体光量に掛ける)。どこまで暗くするかは「MIDI/OSC」タブの「効き具合」(標準70%。100%なら無音で真っ暗)
- **フレーズ → 照明の切り替え**: BLT から `/dmx/phrase` にフレーズの名前を送ります。次のどちらかが動きます
  1. `/dmx/phrase/<名前>` を OSC アドレスに付けた割り当て(例: `/dmx/phrase/chorus` にストロボのパッドの動作)。OSCラーンで、BLT から1回送って登録してもよい
  2. 割り当てが無ければ、同じ名前のシーン。英語(`chorus`)でも日本語(`サビ`・`イントロ`・`バース`・`ブリッジ`・`アップ`・`ダウン`・`アウトロ`)でもよい。`verse2` のような番号つきは `verse` / `バース` として扱います
- 「MIDI/OSC」タブに、受けているRGBの色と、最後に受けたフレーズが出ます

BLT 側の設定例です(BLT の式は Clojure。関数の名前などは BLT のバージョンで変わることがあるので、BLT のドキュメントの「Expressions」「Shows」も見てください)。

```clojure
;; トリガーの Global Setup: OSCの送り先(このアプリのPCのIPとポート)
(swap! globals assoc :dmx (osc/osc-client "127.0.0.1" 9000))

;; トリガーの Tracked Update(再生中、状態が届くたび。Watch は Master Player に)
;; 遅れを打ち消すため、LEAD 秒先の波形の色を読み、「LEAD 秒後にこの色」として送る
(let [lead   0.3     ; 先読みする秒数(状態が届く間隔 約0.2秒 より長く)
      light  0.05    ; 照明が遅れて光るぶん(DMXの送信・機材の反応。秒)
      n      (.getDeviceNumber status)
      ms     (.getTimeFor (org.deepsymmetry.beatlink.data.TimeFinder/getInstance) n)
      speed  (org.deepsymmetry.beatlink.Util/pitchToMultiplier (.getPitch status))
      detail (.getLatestDetailFor (org.deepsymmetry.beatlink.data.WaveformFinder/getInstance) n)]
  (when (and detail (.isPlaying status) (pos? ms))
    ;; 曲の中の時間は再生速度(ピッチ)のぶん速く進むので、先読みする量も速度を掛ける
    (let [ahead (+ ms (* lead 1000 speed))
          start (org.deepsymmetry.beatlink.Util/timeToHalfFrame ahead)
          segs  (range (max 0 (- start 8)) (min (+ start 8) (.getFrameCount detail)))  ; その前後 約0.1秒を平均
          cols  (map #(.segmentColor detail % false) segs)
          avg   (fn [f] (/ (reduce + (map f cols)) (max 1 (count cols)) 255.0))
          ;; 波形の高さ(0〜31)の平均を 0〜1 に
          size  (/ (reduce + (map #(.segmentHeight detail % false) segs)) (max 1 (count segs)) 31.0)]
      (when (seq cols)
        (osc/osc-send (:dmx @globals) "/dmx/main/rgb/at"
                      (float (avg #(.getRed %))) (float (avg #(.getGreen %))) (float (avg #(.getBlue %)))
                      (float (- lead light)))
        (osc/osc-send (:dmx @globals) "/dmx/level/at" (float (min 1.0 size)) (float (- lead light)))))))
```

フレーズは、BLT の **Show** に **Phrase Trigger** を作り(サビ用・イントロ用など)、その「Started」の式で送ります。

```clojure
(osc/osc-send (:dmx @globals) "/dmx/phrase" "chorus")
```

- 波形の色は rekordbox で解析した曲の「RGB(カラー)波形」から取ります。3バンド波形の曲では色の意味が変わります
- 波形の色は暗い所・白っぽい所もあるので、鮮やかな色にしたいときは BLT の式で彩度・明るさを上げてから送ってください

### オート(曲の情報で自動、無ければ待機の色)

「MIDI/OSC」タブの **オート** をONにすると、人が操作しなくても照明が動きます。

- **曲の情報が届いている間**(BLT から `/dmx/main/rgb`・`/dmx/level`・`/dmx/phrase` のどれかが来ている間): 波形の色・大きさで色と明るさが変わり、フレーズでシーン・割り当て・組み込みの動きが切り替わります。テンポは Ableton Link
- **フレーズの組み込みの動き**: フレーズに割り当てもシーンも無いときは、ムービングの動きとメイン/サブ色の入れ替え方をフレーズに合わせて変えます

  | フレーズ | ムービング | 色 |
  |---|---|---|
  | イントロ / アウトロ | 円・4小節で1周 | 8拍でグラデーション |
  | バース | 8の字・2小節 | 4拍ごとに入れ替え |
  | ブリッジ | 左右・1小節(左右対称) | 4拍でグラデーション |
  | アップ | 前後・2拍(揃える) | 2拍ごとに入れ替え |
  | サビ | クロス・2拍(左右対称) | 1拍ごとに入れ替え |
  | ダウン | ウェーブ・2小節 | 8拍でグラデーション |

- **フレーズの情報が来ない曲**(rekordbox でフレーズを解析していない曲など): 16拍ごとに、波形の大きさ(`/dmx/level` を数秒ならした「盛り上がり」)で見た目を選びます(大きい: サビ / 中くらい: バース / 小さい: ダウン)
- **サビの頭で全開**: アップ・ブリッジからサビに入った瞬間、1拍だけ今の色で全開にします(レーザーは除く)
- **手動優先**: MIDIコントローラー・キーボードで操作したら、その後2分間(設定で変更、0でなし)はオートが照明を変えません(フレーズ・色・明るさ・待機の色)。操作をやめると戻ります。画面の「オートに戻す」ですぐ戻せます。画面のクリックは数えません
- **届かなくなったら**(DJ機器が止まった・BLTやDJ機器がつながっていない。既定で5秒): 全体を **薄い水色**(明るさ35%)でなめらかに光らせて待ちます。ムービングは止まり、レーザーは出しません。色・明るさ・待つ秒数は画面で変えられます。全体光量のフェーダーとブラックアウトは待機中も効きます

### モニターの無いLinuxでオート(BLT と一緒に常駐)

照明卓用の小さなPCに、DJ機器と同じネットワークでつないで置いておくだけで、電源を入れれば自動で動く構成です。

```
CDJ / XDJ ──(Pro DJ Link・LAN)── Linux PC ──(USB-DMX または Art-Net)── 照明
                                  ├ Beat Link Trigger(仮想の画面の中)
                                  │   ├ テンポ・拍 → Ableton Link
                                  │   └ 波形の色・大きさ・フレーズ → OSC(127.0.0.1:9000)
                                  └ dmxctl --headless(オート)
```

- `dmxctl --headless`: 画面を出さずに動きます(モニター・X11・SDL2 は不要)。起動すると、OSC受信・テンポの元(Ableton Link)・オートを必ずONにします。様子は標準出力に出ます(待機/受信中・フレーズ・BPM・Linkの台数)
- Beat Link Trigger は画面のあるアプリなので、仮想の画面(Xvfb)の中で動かします。画面を出さずに動く [Open Beat Control](https://github.com/Deep-Symmetry/open-beat-control) もありますが、波形・フレーズは扱えないので、ここでは BLT を使います

**準備**

1. 照明の設定(機材・出力・シーン)は、画面のあるPC(または同じPCをモニターにつないで)で作り、`~/.config/dmxctl/` をこのPCにコピーします。フレーズ用のシーン(`サビ` など)を作っておくと、組み込みの動きの代わりにそちらを呼び出します
2. このPCで `./scripts/build-linux.sh`(または Release の tar.gz の `dmxctl` を `dist/linux/` に置く)
3. BLT の公式の `.deb` を入れます(`sudo apt install ./beat-link-trigger_*.deb`)。入った場所が `/opt/beat-link-trigger/bin/Beat Link Trigger` でなければ、`~/dmxctl/blt.env` に `BLT_CMD="起動コマンドの場所"` と書きます
4. `./scripts/linux/install-headless.sh` で、dmxctl と BLT を電源を入れたら動くようにします(ユーザーのサービス。`--no-blt` なら dmxctl だけ)。USB-DMX のグループに入ったときは、一度再起動してください

**BLT の設定(最初に1回)**

仮想の画面に VNC で入って設定します。設定は BLT が覚えていて、次からはそのまま動きます。

1. このPCで、VNC つきで BLT を起動し直します

   ```
   systemctl --user stop beat-link-trigger
   BLT_VNC=1 ~/dmxctl/blt-headless.sh
   ```

2. 手元のPCから `ssh -L 5900:localhost:5900 ユーザー@このPC` でつなぎ、VNC ビューアで `localhost:5900` を開きます
3. BLT で次を設定します
   - Ableton Link: マスタープレイヤーのテンポと拍を Link に流す設定にする(BLT のバージョンによっては Carabiner を別に入れる必要があります)
   - トリガーを1つ作り、Watch を Master Player に。Global Setup と Tracked Update に [Beat Link Trigger との連携](#beat-link-trigger-との連携) の式を入れる(波形の色・大きさを先読みで送る)
   - フレーズを使うなら、Show に Phrase Trigger を作り、Started で `/dmx/phrase` を送る
4. BLT を終了して(設定が保存されます)、端末で Ctrl+C。`systemctl --user start beat-link-trigger` で元に戻します

**動かしているときの確認**

```
journalctl --user -u dmxctl-headless -f
```

`待機(薄い水色)` → DJ機器が曲を再生すると `曲の情報を受信中(フレーズ: chorus)` のように変わります。

- 止める: `systemctl --user stop dmxctl-headless`(安全な値を送ってから止まります)。設定を画面で直したいときは、止めてから画面のあるほうで起動します
- DJ機器と同じネットワークにつなぐこと(BLT は rekordbox と同じPCでは動かせません)

## バックアップ

- **起動のたび**と、**別のファイルを開く前**に、保存ファイルを設定フォルダの `backups\project-日付-時刻.json` に自動で残します(最新20個。設定フォルダは [はじめに](#はじめに最初の準備) の最後を参照)

# ビルド・動作環境

## ビルドと起動(Windows)

```
cargo run --release
```

ビルドには Rust と、Visual Studio Build Tools の「C++ によるデスクトップ開発」が必要です(Ableton Link のC++をいっしょにビルドするため)。

`target\release\dmxctl.exe` 単体で動きます(約8MB)。設定は `%APPDATA%\dmxctl\project.json` に自動保存されます。

## Mac で使う

同じソースから Mac 用のアプリ(`DMX Controller.app`、Apple Silicon と Intel の両方で動くユニバーサル版)を作れます。作るのは Mac の上で行います(Windowsからは作れません)。

**Macで作る**

1. Rust を入れる: https://rustup.rs の手順(ターミナルで1行)
2. Xcode のコマンドラインツールを入れる: `xcode-select --install`
3. このフォルダをMacにコピーして、ターミナルで `./scripts/build-mac.sh`
4. `dist/mac/DMX Controller.app` ができます(配布用の zip も同じ場所)

**MacからWindows版を作る**: MinGW-w64 を入れて(`brew install mingw-w64`)、`bash ./scripts/build-windows-mingw.sh`。`dist/windows/dmxctl.exe`(単体で動く。追加のDLLは不要)と配布用のzipができます。

**Macが手元に無い場合**: GitHub で PR を作ると、`.github/workflows/build.yml` により Mac 用・Windows 用・Linux 用がビルドされます(ビルドが通るかの確認。ただの push ではテストだけ)。`v` で始まるタグ(例: `v0.2.0`)を push すると、そのビルドの成果物(zip / tar.gz)が GitHub の Release に添付されます。

**Macでの違い・注意**

- 設定の保存場所: `~/Library/Application Support/dmxctl/`(Windowsの `%APPDATA%\dmxctl\` と同じ中身。`project.json` をコピーすればそのまま使えます)
- 保存のショートカットは ⌘S。ほかのキーは同じ
- USB-DMX(FT232系): Mac標準のドライバで `/dev/cu.usbserial-…` として見えます(「出力」タブのCOMポートの一覧に出ます)。D2XX を使う場合は FTDI の `libftd2xx.dylib` を入れてください
- 簡易署名のアプリなので、ダウンロードしたものを初めて開くときは「開発元を確認できません」と出ます。Finderでアプリを右クリック →「開く」で開けます
- 初めて Art-Net / Ableton Link / OSC を使うとき、「ローカルネットワーク上のデバイスの検索と接続」の許可を求められます。許可してください

## Linux で使う

Linux(X11 / Wayland のどちらでも)で動きます。**デスクトップ環境の無いLinux**(コンソールだけのPC・Raspberry Pi など)でも、画面に直接(KMS/DRM)出して使えます([デスクトップ環境の無いLinuxで使う](#デスクトップ環境の無いlinuxで使うkmsdrm))。作るのは Linux の上で行います。

**Linuxで作る**

1. Rust を入れる: https://rustup.rs
2. ビルドに要るものを入れる
   - Ubuntu / Debian: `sudo apt install build-essential pkg-config libasound2-dev libudev-dev libsdl2-dev`
   - Fedora: `sudo dnf install gcc-c++ pkgconf alsa-lib-devel systemd-devel libatomic SDL2-devel`
   - Arch: `sudo pacman -S base-devel alsa-lib sdl2`
3. `./scripts/build-linux.sh`
4. `dist/linux/dmxctl`(デスクトップ環境用)と `dist/linux/dmxctl-kmsdrm`(デスクトップ環境の無い画面用)ができます(配布用の `DMX-Controller-linux.tar.gz` も同じ場所)。デスクトップでは `./dmxctl` で起動

GitHub の Release に付いている Linux 版(`DMX-Controller-linux.tar.gz`)は Debian 13 の中で作っているので、**Debian 13 以降**で動きます(今のところ Ubuntu 24.04 以降でも動きます)。それより古い Linux では起動できない(`GLIBC_2.xx not found` と出る)ので、上の手順でそのPCの上で作ってください。

- `dmxctl` は SDL2 を使わないので、デスクトップ環境のあるPCなら追加で入れるものはありません。`dmxctl-kmsdrm` は SDL2 を使う機能(`kmsdrm`)入りで、動かすPCに SDL2 が要ります(Ubuntu / Debian: `sudo apt install libsdl2-2.0-0`)
- SDL2 を入れずに作るときは `DMXCTL_NO_KMSDRM=1 ./scripts/build-linux.sh`(`dmxctl` だけ作ります)

**Linuxでの違い・注意**

- 設定の保存場所: `~/.config/dmxctl/`(`XDG_CONFIG_HOME` があればその下)。中身は Windows / Mac と同じ
- 保存のショートカットは Ctrl+S
- 日本語フォント: Noto Sans CJK があればそれを使います(無ければ fontconfig が選ぶ日本語フォント)。文字が□になるときは `sudo apt install fonts-noto-cjk` など
- USB-DMX(FT232系): 標準のドライバで `/dev/ttyUSB0` などとして見えます。開けないときは `sudo usermod -aG dialout $USER` のあとログインし直してください
- D2XX を使う場合は FTDI の `libftd2xx.so` を入れ、標準のドライバを外します(`sudo rmmod ftdi_sio`)。ふつうは COMポート方式で十分です
- MIDI・音声入力は ALSA を使います(PipeWire / PulseAudio の環境でもそのまま動きます)
- メニューに出したいときは、`dmxctl` を PATH の通った場所に置き、`dmxctl.desktop` を `~/.local/share/applications/` にコピー
- ファイアウォール(ufw / firewalld)を有効にしている場合は、使う機能のUDPポートを開けてください: OSC受信(既定 9000)、Ableton Link(20808)。Art-Netの送信だけなら不要です
- 終了のシグナル(Ctrl+C・`kill`・ログアウト・シャットダウン)を受けたときも、安全な値(レーザーOFF・明るさ0)を送ってから止まります
- NDI を使うときは NDI SDK のライブラリが要ります([Linux で NDI を使う](#linux-で-ndi-を使う))

### Linux で NDI を使う

Linux には NDI Tools が無いので、**NDI SDK for Linux** に入っているライブラリ(`libndi.so.6`)を入れます。ライブラリは配布条件のためアプリに同梱していません。NDI を使わないなら不要です(無くてもアプリは起動します)。

```sh
curl -fLO https://downloads.ndi.tv/SDK/NDI_SDK_Linux/Install_NDI_SDK_v6_Linux.tar.gz
tar -xzf Install_NDI_SDK_v6_Linux.tar.gz
sh Install_NDI_SDK_v6_Linux.sh       # NDI SDK の使用許諾が出るので、読んで同意するなら y(今いるフォルダに「NDI SDK for Linux」ができる)
sudo cp -P "NDI SDK for Linux/lib/x86_64-linux-gnu/"libndi.so* /usr/local/lib/
sudo ldconfig
```

- 入ったかの確認: `/sbin/ldconfig -p | grep libndi` に `libndi.so.6` が出ればOK。dmxctl の2ページ目の設定パネルで NDI のソースが選べるようになります
- 64bit の Raspberry Pi OS では、`x86_64-linux-gnu` の代わりに `aarch64-rpi4-linux-gnueabi` のフォルダのものを使います
- `sudo` を使わずに試すときは、置いた場所を直接指定して起動します: `DMXCTL_NDI_LIB="$PWD/NDI SDK for Linux/lib/x86_64-linux-gnu/libndi.so.6" ./dmxctl`
- 入れたあとは、ダウンロードしたファイルと「NDI SDK for Linux」のフォルダは消してかまいません

### デスクトップ環境の無いLinuxで使う(KMS/DRM)

デスクトップ環境(X11 / Wayland)が無いPCでは、`dmxctl-kmsdrm` を **コンソール(tty)から起動するだけ** で、画面全体に直接表示します(SDL2 の KMSDRM を使用)。照明卓専用の小さなPCや Raspberry Pi で、余計なものを入れずに動かせます。

**準備**

1. `./scripts/build-linux.sh` で作った `dmxctl-kmsdrm`(`kmsdrm` 機能入り。Release の tar.gz にも入っています)を使います。動かすPCに SDL2(`libsdl2-2.0-0`)、OpenGL ES の動くGPUドライバ(Mesa。ふつうは入っています)、日本語フォント(`fonts-noto-cjk`)を入れます
2. 画面とキーボード・マウスを使えるよう、ユーザーを `video` と `input` のグループに入れて、ログインし直します

   ```
   sudo usermod -aG video,input,dialout $USER
   ```

   (`dialout` は USB-DMX 用)。`input` に入っていないと、画面は出てもキーボード・マウスが効きません(画面下に知らせが出ます)

3. コンソールにログインして `./dmxctl-kmsdrm` で起動します。SSH から起動することもできます(画面はそのPCにつないだモニターに出ます)

**操作・違い**

- 画面全体に表示します。拡大率は画面の大きさから自動で決めます(1920×1080 なら1.25倍)。変えたいときは `DMXCTL_SCALE=1.5 ./dmxctl-kmsdrm` のように指定します
- **終了**: 「ファイル」メニューの「終了」、または Ctrl+Q(閉じるボタンが無いため)。起動した端末での Ctrl+C でも安全に止まります
- ファイルを選ぶ画面(別名で保存・開く)は出せないので、「ファイル」メニューには出ません。設定は今までどおり自動保存され、「バックアップから戻す」は一覧から選べます
- タッチパネル: 触った所をクリック(触ったまま動かすとドラッグ)
- トラックパッド: 1本指でカーソルを動かす、軽く叩くと左クリック、2本指で叩くと右クリック、2本指で動かすとスクロール(指の動きに中身がついてくる向き)。押し込むクリックも使えます
- 日本語入力(IME)は使えません。名前の欄などには英数字を入力してください
- 他のアプリ(デスクトップ環境など)が画面を使っている間は起動できません
- KMSDRMを使うかどうかは、ふつうは自動で決まります(環境変数 `DISPLAY` と `WAYLAND_DISPLAY` が無ければ使う)。`--kmsdrm` か `DMXCTL_KMSDRM=1` で必ず使い、`DMXCTL_KMSDRM=0` で使いません

**電源を入れたら自動で起動する(例)**

1. tty1 に自動ログインする

   ```
   sudo systemctl edit getty@tty1
   ```

   で開いたところに次を書いて保存します(`ユーザー名` は自分のもの)

   ```
   [Service]
   ExecStart=
   ExecStart=-/sbin/agetty --autologin ユーザー名 --noclear %I $TERM
   ```

2. `~/.bash_profile` の最後に、tty1 のときだけ起動するよう書きます(`dmxctl-kmsdrm` を置いた場所に合わせる)

   ```
   if [ "$(tty)" = /dev/tty1 ]; then ~/dmxctl/dmxctl-kmsdrm; fi
   ```

   アプリを終了するとコンソールに戻ります(`~/dmxctl/dmxctl-kmsdrm` の前に `exec` を付けると、終了しても自動でもう一度起動します)

## USB-DMX(FT232系)について

このタイプはDMXフレーム(BREAK→スタートコード→スロット)をPC側が作って送り続ける方式です。2通りの接続方法があります。

- **COMポート**: FTDIドライバが作る仮想COMポートに、250000bps 8N2 + BREAK で送信。まずこちらを試してください
- **D2XX**: FTDIのライブラリ(Windows: `ftd2xx.dll`(FTDIドライバに同梱) / Mac: `libftd2xx.dylib`(アプリに同梱) / Linux: `libftd2xx.so`)を実行時に読み込んで直接制御。ライブラリが無くてもアプリ自体は起動します

抜き差しや電源断で切れても、自動で再接続します。

## 設計のポイント

| もの | 中身 |
|---|---|
| 機材定義 | アプリ内の「機材定義」タブで作成・編集(モード・チャンネル・値の範囲・16bit・安全値・カテゴリ)。実体は設定フォルダの `fixtures/*.json` で、手書きも可 |
| 対象の指定 | 機材単体 / グループ / 同機種すべて / すべて。機能名(`dimmer`, `color` など)で指定するので、機種が違っても同じ割り当てが効く |
| パッドの動作 | フェーダー(連続) / 押している間 / トグル / ワンショット |
| 割り当てできる動作 | チャンネル値、シーン呼出(フェード付き)、エフェクト/チェイスON/OFF、ムービングの動き、色、位置プリセット、テンポ、ページ切替、全体光量、ペア、ブラックアウト など |
| 割り当ての入力 | MIDI(ノート/CC。ページ別にできる)、パソコンのキーボード、OSCアドレス |
| エフェクト | 対象チャンネルを 最小〜最大 で周期的に動かす(サイン/三角/ノコギリ/矩形/ランダム、位相・機材ごとのずれ) |

出力は専用スレッドで40Hz固定(画面の更新頻度とは無関係)。

## 性能の目安

負荷をかけた構成(機材8台・エフェクト・チェイス・ペアを動かしながら、Art-Netを40Hzで送出)での実測です(このPC: 14論理コア)。

| 項目 | 結果 |
|---|---|
| 1フレームの合成(機材16台・割り当て64件・エフェクト4件・チェイス2件・ペア3件) | 約12µs(40Hzの周期25,000µsの0.05%) |
| パッドLEDの計算(80個) / MIDI 1メッセージ | 約30µs / 約0.4µs |
| DMX出力の間隔 | 平均25.0ms(40回/秒)。p99は26ms前後 |
| **CPUを全コア使い切っているとき** | 出力は40回/秒のまま。間隔の最悪は+10ms程度 |
| メモリ | 起動後 約90MB(Private)で一定。100秒以上動かしても増えない |
| CPU(1コア換算) | コントロール/マップ表示 約2〜3% / **前面が他のアプリのとき 約1.4%** / 最小化 0% / モニター表示 約11% |
| LEDバー 32ピクセル×2本 + ピクセルエフェクト2つを追加した構成 | 1フレームの合成 約36µs(周期の0.14%) |
| Link・OSCを有効にしたとき | コントロール表示 約1〜2% / 最小化 約1%(Linkの通信) / **OSCを60回/秒受け続けている間 約5%**。出力は40回/秒・p99 26ms のまま |

- DMXの出力は画面とは別スレッドで動くので、画面の表示状態や、画面が重いことは出力の間隔に影響しません
- 画面の描画は、操作したとき・MIDI入力があったとき・拍の頭(BPM表示)にだけ行います。1回の描画は内容によらず約10〜15msのCPUを使うので、回数を減らすことでCPUを抑えています(モニター表示中は10fps、ウィンドウが前面でないときは通常1秒に1回・モニター4fps)
- 映像などの重いアプリと同居するときは、このウィンドウを最小化するか、他のアプリを前に出しておくと、CPU使用はほぼゼロになります
- 診断: 環境変数 `DMXCTL_PERF=1` を付けて起動すると、画面下に「描画回数/秒と1回あたりの時間」を表示します
- 環境変数 `DMXCTL_NO_MIDI=1` を付けて起動すると、MIDI機器に自動接続しません(本番で動かしているアプリのAPC mini mk2を、試し用のもう1つのアプリが奪わないように)
- ベンチマーク: `cargo test --release perf -- --ignored --nocapture`

## ライセンスについて(Ableton Link)

Ableton Link は GPLv2(以降)で配布されているため、Linkを組み込んだこのアプリ(exe)を他の人に配る場合は、GPLに従ってソースコードを一緒に公開する必要があります。個人で使う分には制限はありません。Linkのソースは `third_party/link/`(ライセンス文書も同梱)にあります。
