# MCP

`dmxctl mcp` は、Claude Code などの AI のクライアントから dmxctl を操作するための MCP (Model Context Protocol) のサーバーです。標準入出力で JSON-RPC を受け取り、起動中の本体の制御の窓口へ中継します。操作の検証・安全処理は [CLI](cli.md) の `ctl` と同一で、MCP 用の別の処理はありません。

## 使い方

1. 操作する本体を、制御の窓口を開いて起動します。画面なしなら `serve`、画面のある通常の起動なら `--control` を付けます

   ```
   dmxctl serve --project show.json
   dmxctl --control --project show.json --output none --inputs none --no-autosave
   ```

   試用には本番とは別のプロジェクトを指定します。上の例はどちらも実機送信・入力・自動保存を無効にして起動します。画面版の `--control` は制御の接続を有効にするだけで、実機送信・入力・自動保存は既定で有効です。実機送信の有無は本体の `--output none` または `--output live` で指定します

2. AI のクライアントに、`dmxctl mcp` をサーバーとして登録します。Claude Code では次のとおりです。Mac の場合、実行ファイルは `DMX Controller.app/Contents/MacOS/dmxctl` です

   ```
   claude mcp add dmxctl -- /path/to/dmxctl mcp
   ```

   本体の接続先を `--listen` で変更したときは、`dmxctl mcp --connect 127.0.0.1:9191` のように同じ番号を指定します。接続先はループバック IP に限定しています

   対応する MCP プロトコルの版は `2025-06-18` と `2024-11-05` です。クライアントが別の版を指定した場合は `2025-06-18` を提示します

3. クライアントから「機材の一覧を見て、1番のディマーを半分にして」のように依頼します

## ツール

| 名前 | 内容 |
|---|---|
| `status` | 本体の状態。BPM・拍・出力先・入力・送信の有無・設定の版など |
| `fixture_list` | 機材の一覧。ID・名前・機種と、`attrs` に現在のモードで指定できる属性名 |
| `fixture_set` | 機材1台の属性の基準値を変更する。値は DMX(0〜255) |
| `control_list` / `control_press` | 画面・MIDI と同一の割り当ての一覧と、押下・解放・スライダーの変更。押下は期限で必ず解放される |
| `command` | `ctl command` と同一の操作を1つ実行する。全体光量・シーン・色・BPM・フラッシュなど |
| `output_snapshot` / `output_check` | 安全処理後の最終の出力値の取得と、条件の検証 |
| `wait` | フレーム数・拍数・時間、または出力の条件を満たすまで待機する |
| `explain` | 次のフレームで、その属性の値がどのように決定されたか |
| `schema` | 設定の形・現在値・読み取り専用の項目・使える操作の一覧 |
| `edit` | 設定の編集。`dry_run: true` で事前に検証できる |
| `project_save` | 現在の設定をファイルに保存する |

## 安全面

- ARM・安全設定の変更・レーザーの合図は、`ctl` と同様に実行できません。本体の窓口が拒否し、理由をツールの失敗として返します
- 禁止の値と動いてよい範囲は、どの操作から来た値でも、本体が出力の直前に補正します
- 本体の停止、記録のファイル、設定の読み込み直し・復元は、ツールにしていません。必要なときは `ctl` を使います
- MCP の接続を閉じても、本体は停止しません。押下中のボタンは期限で解放されます
