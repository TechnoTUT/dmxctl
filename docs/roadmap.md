# 今後の予定

## 機能の候補

- sACN 出力
- レーザーのパターン名一覧。パターン番号を名前で選べるようにする

## CLI・自動操作で残っている作業

画面を見ずに、GUI版と同じ実行状態を操作・検証できるようにするのが目的です。今の機能は [CLI](cli.md) にあります。GUI・CLI・将来の MCP で操作の検証処理を共有し、シミュレーションも安全処理後の最終DMX値を使います。

- GUI の数値・名前などの直接編集を、タブごとに共通の編集処理へ移す。入力途中の無効な値は出力へ反映せず、入力欄の下書きとして持つ
- 使用中の機材定義のチャンネル構造を変えるとき、定義とプロジェクトを同時に移行できるようにする。今はパッチを外して保存してから変える
- GUI の観測履歴 `state_change` から個々の操作を再現する。今は `state_change` を含む記録のシナリオ出力を拒否する
- 実時間の拍の位相・進行中のフェード・音声や映像を含む実行状態の復元
- 実機入力サービスの再接続と、大規模な機材構成での継続的な負荷測定

通常の操作から安全設定をバイパスできない方針は維持します。安全設定そのものの編集を扱う場合は、演出の操作と区別して仕様を決めます。

## 3Dプレビュー

描画機能の内製は保留し、別に開発している [dmxsim](https://github.com/TechnoTUT/dmxsim) との Art-Net 接続を先に検証します。受信仕様、配布・起動方法、ライセンス、性能は連携前に確認します。

### 役割分担の案

- dmxctl: GUI・CLIによる操作、設定の検証、DMX合成と安全処理、記録、入力・シナリオの再現、出力値の検証
- dmxsim: DMX値から機材の見た目を再現する処理、三次元の配置・向き・ビーム、表示品質と描画負荷の調整
- 共通の接続仕様: ユニバース番号、開始アドレス、機材・モードとチャンネルの対応、16bit値、座標・角度の規約。どの情報を設定ファイルで共有するかも決める

Art-Net で送るDMX値には、機材の配置やチャンネルの意味は含まれません。パッチと機材定義を渡す方法を検討し、3D固有の配置やビーム幅などの情報は dmxsim 側で扱う案とします。

### 接続を検証する順序

1. dmxsim の対応機材・モード、受信ユニバース、起動方法を確認する
2. 同じPCの `127.0.0.1:6454` に ArtDmx を送り、既知の値で表示が一致するか確認する。機材を並べたり USB-DMX をつないだりせずに検証できる経路を作る
3. 実機出力とは独立した、プレビュー用の Art-Net 出力を加える。今の `--output none` は Art-Net も止めるので、そのままでは外部ビューアーへ値を送れない。プレビューのために、保存済みのUSB・ネットワーク出力をまとめて有効にする運用にはしない
4. プレビューには安全処理後の最終DMX値を渡す。通常のフレームだけでなく、ブラックアウト・停止時の安全値も対象にする。内部ユニバースと Art-Net の番号の対応を明示し、実機向けの出力設定は変えない
5. GUI・CLI からビューアーを開く・閉じる・必要なら画像を保存する操作を整える。まず別プロセスでの連携を検証し、アプリ内の別ウィンドウとして組み込むかは dmxsim の構成を見て決める

### 守る要件

- GUI から別ウィンドウで開いて確認できる操作感を目指す
- 起動前は3D描画用の資源を確保しない。終了時は、自分が起動した描画処理・プロセスの資源を解放する
- 描画が遅れてもDMX出力を待たせず、最新の状態を表示する
- 内蔵GPUで使えることを目標とし、基準のPCと機材数を決めて性能を測る
- 機材ごとの角度やビーム幅など、表示のための追加情報と精度の限界を明示する
- AI による正確な出力値の検証は、内部スナップショット・ログを使う。UDP経由の受信・3D表示の確認とは分けて扱う

サブモジュール化は、ソースからの同時ビルドや描画ライブラリの共有が必要かを確認してから決めます。

## Model Context Protocol (MCP)

- CLI と共通の操作APIへつなぐアダプターとして加える
- 操作一覧・引数の仕様・状態取得を提供し、実機送信や安全処理の条件も共通にする
- MCP の接続を閉じても、GUI・常駐本体の実行は続けられる構成にする
- 今の制御用JSONプロトコルを MCP とは呼ばず、導入時に仕様と互換性を検証する
